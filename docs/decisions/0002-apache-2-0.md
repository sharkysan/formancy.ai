# 0002 — Apache-2.0 for everything, no dual licensing

- **Status:** accepted
- **Date:** 2026-09-19
- **Deciders:** Daniel Bacher
- **Verified by:** Not mechanically enforced. The root `LICENSE` carries the
  Apache-2.0 text, `NOTICE` carries the attribution it provides for, and all ten
  publishable packages declare `"license": "Apache-2.0"` with
  `publishConfig.access: "public"` — but nothing compares them. `pnpm check:pkg`
  runs publint and attw, and neither checks a licence value, so a package
  published under something else would pass CI.

## Context

form.io is licensed OSL-3.0. Under it, providing a service to external users
counts as distribution and triggers source disclosure. That is the single
most-cited reason people go looking for an alternative, so it is also the thing
any licence chosen here is read against. MIT was the obvious default: shortest,
most familiar, least to argue about.

## Decision

Apache-2.0 across every package, with no dual licensing and no
relicensed-later escape hatch.

## Consequences

**What it buys.** Against OSL-3.0, Apache-2.0 is the clearest available
statement that there is no catch, which is the whole positioning. It is also
what the infrastructure companies this project wants to be grouped with use, so
it needs no explanation to a buyer's open-source programme office.

**What it costs.** A competitor — including a large cloud provider — may operate
formancy as a service and contribute nothing back. That risk is accepted. The
answer to it is the open-core line ([0003](0003-open-core-line.md)) and the work
of running the platform, not a licence restriction.

**What it forecloses.** There will never be a proprietary edition of this code,
because there is no second licence to issue it under. One question stays open:
whether contributions are taken under a CLA or a DCO is **not yet decided**. A
CLA preserves the option of proprietary enterprise builds but reads as "they
plan to relicense" and measurably suppresses contributions on a young project; a
DCO is lighter but makes relicensing effectively impossible once there are
contributors. The repository is closed to outside contributions until it is
settled, because it cannot be settled retroactively — see
[`GOVERNANCE.md`](../../GOVERNANCE.md). Separately, the licence's non-grant of
trademark rights is only worth something if the mark exists: register the word
mark before the project has traction.

## Alternatives considered

**MIT.** Rejected on four counts. Apache-2.0 carries an express patent grant
with a retaliation clause, which MIT lacks and which a programme office looks
for specifically. It explicitly does not grant trademark rights, which matters
for a project that intends to compete commercially under its own name. It
provides for NOTICE-file attribution. And it is the licence of the companies
this one wants to be compared to.

**OSL-3.0, or another licence with the same reach.** Rejected: it is the problem
being solved, and adopting it would make the project a second instance of the
thing people are trying to leave.

**Dual licensing, or Apache-2.0 with a relicense-later hatch.** Rejected: both
reintroduce exactly the doubt the licence choice exists to remove.
